# Three-Agent Sync Protocol

This protocol is for the search/schema, threshold, and frontend/reporting repair effort described in `yield-update/THREE_AGENT_FIX_PLAN.md`.

## Status Files

Each agent writes only one status file:

- Agent A writes `yield-update/status/agent_a_search_schema_status.md`
- Agent B writes `yield-update/status/agent_b_threshold_status.md`
- Agent C writes `yield-update/status/agent_c_frontend_reports_status.md`

Do not edit another agent's status file.

## Checkpoint Format

Append one checkpoint at the end of each meaningful task group:

```markdown
## YYYY-MM-DD HH:MM - Agent <A|B|C>

Status: in_progress | blocked | ready_for_review | complete
Task group: <short name>
Files touched:
- <path>

Done:
- <one-line result>

Next:
- <one-line next step>

Public interfaces changed:
- <schema/function/endpoint change, or none>

Needs from other agents:
- none
```

Keep checkpoints short. These files are coordination surfaces, not long-form notes.

## Required Checkpoints

Agent A must checkpoint after:

1. Updating the refresh search list.
2. Updating Worker schema prompt/normalization.
3. Updating provider info.
4. Final Worker syntax check or documented verification.

Agent B must checkpoint after:

1. Implementing threshold helpers.
2. Implementing scenario probability normalization.
3. Wiring deterministic alerts into the Worker postprocess.
4. Final sample alert checks.

Agent C must checkpoint after:

1. Adding frontend probability compatibility helpers.
2. Adding S3 chart support.
3. Updating provider display and zoom/responsive sizing.
4. Updating README/local report notes.
5. Final frontend/report verification.

## Cross-Agent Reads

Before finalizing, each agent should read the other two status files if they exist.

If a file does not exist yet, continue with your owned work and note the assumption in your own status file.

## Blocking Rules

If blocked:

1. Write `Status: blocked`.
2. Put the exact question under `Needs from other agents`.
3. Continue any non-overlapping work if possible.

The coordinator is responsible for reading status files and resolving cross-agent questions.

## Shared Interface Decisions

The canonical Worker entry must use:

- `scenario_probs.s1_no_pivot`
- `scenario_probs.s2_tariff_rollback`
- `scenario_probs.s3_oil_trap`
- `scenarios.s1.direction`
- `scenarios.s1.key_signal`
- `threshold_alerts` generated by code

Old `scenarios.sN.prob` may be read as fallback but should not be emitted as the canonical contract.

## Verification Checklist

Before final handoff, the coordinator should confirm:

- `cloudflare/src/worker.js` parses with `node --check`.
- `doRefresh()` includes all 16 required searches from `docs/data_sources.md`.
- Worker postprocess produces top-level `scenario_probs`.
- Threshold alerts use `WARNING:` or `CRITICAL:` prefixes.
- GOP approval, 10Y, 30Y, 2s10s, and Fed hike sample checks pass.
- Frontend can read both canonical `scenario_probs` and old `scenarios.sN.prob`.
- S3 history chart exists and is drawn.
- README describes local JSON versus Worker KV clearly.
